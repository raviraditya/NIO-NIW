# NIO-NIW

MATLAB code for *Near-Inertial Currents and Waves Generated by Tropical Cyclones in the North Indian Ocean and Their Vertical Redistribution* (Singh \& Behera, JGR: Oceans).

Analyses the near-inertial response to four North Indian Ocean tropical cyclones — Fani (2019), Kyarr (2019), Amphan (2020) and Tauktae (2021) — using HYCOM GLBy0.08 reanalysis fields with ERA5 forcing.

## Before you run anything

Each script starts with a short config block. Set `DATA\_DIR` to the folder holding the input data, and `GSW\_PATH` to your copy of the Gibbs SeaWater toolbox. `DATA\_DIR` is expected to contain subfolders named `HYCOM`, `IMD`, `Stress`, `Currents`, `INCOIS\_OHC`, `SST`, `Stokes` and `ARGO`.

Requires MATLAB with the Signal Processing and Statistics toolboxes, plus GSW (http://www.teos-10.org).

## Order to run

|Script|What it does|
|-|-|
|`nike\_main\_analysis.m`|Reads HYCOM and ERA5, does the pointwise harmonic fit, writes one `\*\_V17.mat` per cyclone|
|`nike\_postprocess.m`|Reads those `.mat` files, writes the per-cyclone summary statistics|
|`nike\_figures\_main.m`|Figures 2–7, plus S10 and S11|
|`nike\_figures\_supplement.m`|Figures S1–S8|
|`argo\_hycom\_validation.m`|Argo co-location and the HYCOM evaluation (Text S1, Table S1, Figure S2)|
|`nike\_sla\_environment.m`|Sea-level anomaly along each track (Figure S9, SLA rows of Table S2)|

Main has to run first — everything else reads its output. Post should run before the figure scripts, since the main figure script reads the post summaries for a couple of annotations.

`nike\_sla\_environment.m` needs a second path, `SLA\_DIR`, pointing at the folder with the `cropped\_ssha\_YYYY.nc` files. It runs independently of the others.

## Which script makes which figure

* Figure 1 — track map, made separately
* Figures 2–7 — `nike\_figures\_main.m`
* Figures S1–S8 — `nike\_figures\_supplement.m`
* Figure S9 — `nike\_sla\_environment.m`
* Figures S10, S11 — `nike\_figures\_main.m` (written under the `FigS10\_` and `FigS11\_` names)
* Tables 2 and 3 — `nike\_postprocess.m` output
* Table S1 — `argo\_hycom\_validation.m`

## Input data

None of it is redistributed here. Sources are cited in the Open Research Section of the paper:

* HYCOM GLBy0.08 reanalysis — US Naval Research Laboratory
* ERA5 — Copernicus Climate Data Store
* Daily gridded sea-level anomaly — Copernicus Climate Data Store
* Argo profiles — Argo Global Data Assembly Centre
* Best tracks — India Meteorological Department and IBTrACS v4

## Notes

The scripts were written for a Windows layout and use `fullfile`, so they should work on Linux and macOS once `DATA\_DIR` is set.

One HYCOM meridional velocity field (03:00 UTC, 18 May 2020, during Amphan) contains valid data only in the upper 6 m and is excluded wherever it occurs. This is handled in the code.
